# Integración fact_api — plan y registro

**Objetivo:** integración local real con Laravel fact_api, PostgreSQL, cola durable, idempotencia y PDF privados para ventas y compras. Empresa ficticia: sin enviar a SUNAT.

**Arquitectura:** el cobro y su outbox se guardan juntos. Un worker Python reclama filas con SKIP LOCKED y envía una instantánea a un puente autenticado Laravel. Laravel deduplica por UUID y huella, conserva datos, reutiliza sus modelos y PdfService para ventas y una plantilla de recepción para compras. Resultados desconocidos se concilian con el mismo UUID. Archivos privados persistentes, sin credenciales en logs.

**Decisiones:** conservar modificaciones anteriores; usar PostgreSQL para ambos servicios, base independiente para Laravel; no Redis obligatorio; todas las tiendas activas configuradas en modo DEMO; tasas explícitas de demostración; circuito separado para compras; no emisión ni CDR simulados. No commit/push solicitado. La descripción y ejecución ya fueron autorizadas por el usuario.

## Registro de decisiones y revisión

- PostgreSQL upstream necesitó corregir una sentencia ENUM exclusiva de MySQL y columnas duplicadas.
- El servidor PHP incorporado terminó en esta PC; adaptador Windows Python → núcleo HTTP Laravel real. Producción requiere PHP-FPM/nginx, no ese adaptador.
- Dependencias nodev instaladas: 121 referencias de composer.lock comprobadas en caché. Sin claves en Git.
- Revisión independiente detectó fecha UTC, escrituras de archivos fuera del lease y carreras con correcciones. Se corrigieron con fecha Lima explícita, rutas por lease, bloqueo/renombrado PDF y FOR UPDATE de la fuente.
- Se agregó carga privada de originales PDF/XML de proveedores, independiente de sus vistas internas generadas.
- Verificación final: 742 backend (142 omitidas: 600 correctas), 151 frontend; lint y build correctos. PostgreSQL aislado: 41 correctas. Pruebas opt-in HTTP Laravel: 2 correctas, incluyendo creación concurrente, respuesta perdida/repetida, conflicto y PDF.
- Ejemplos locales: siete operaciones completadas, cuatro compras y tres ventas, catorce PDF con SHA-256 comprobados. No se creó una venta donde no existía una.
- No se activó SUNAT ni se modificaron importes, pagos o stock por generar esos ejemplos. No se hizo push.
